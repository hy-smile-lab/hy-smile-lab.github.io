# HY-SMILE 홈페이지 운영 안내

- 저장소: https://github.com/hy-smile-lab/hy-smile-lab.github.io
- 현재 주소: https://hy-smile-lab.github.io/
- 배포: `main`에 변경이 올라올 때, 6시간마다, 또는 Actions 탭에서 수동 실행 시 자동 빌드·배포 (GitHub Pages)

## 1. 도메인 연결

### 1-1. 개인 도메인(www.○○○.com) 연결
1. 도메인 구입(가비아, Cloudflare, Namecheap 등)
2. 도메인 업체 DNS 설정
   - `www` → **CNAME** → `hy-smile-lab.github.io`
   - 루트(@) 주소도 쓰려면 **A** 레코드 4개: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
3. GitHub 저장소 → Settings → Pages → Custom domain에 `www.○○○.com` 입력 → 저장 → DNS 확인 후 **Enforce HTTPS** 체크
4. 저장소에 `public/CNAME` 파일 생성(내용: `www.○○○.com` 한 줄) → 도메인 정보가 저장소에 같이 기록됨

사이트는 루트 경로(`/`) 기준으로 빌드되므로 코드 수정 없이 도메인만 바꾸면 됨.

### 1-2. 한양대 주소(○○○.hanyang.ac.kr)로 이전
1. 한양대 정보통신처에 서브도메인 요청: `○○○.hanyang.ac.kr` → **CNAME** → `hy-smile-lab.github.io`
2. Settings → Pages → Custom domain을 `○○○.hanyang.ac.kr`로 변경, `public/CNAME` 내용도 변경
3. 이전 도메인(www.○○○.com)은 도메인 업체에서 새 주소로 포워딩(301) 설정하면 기존 링크 유지

학교 서버로 직접 옮기는 경우: `npm run build` 결과물(`out/` 폴더)이 정적 파일이라 웹서버에 그대로 올리면 동작함.

## 2. 구글 드라이브 자동 반영

### 드라이브 폴더 구조
```
<연동 폴더>/                              ← 이 폴더를 서비스 계정에 '뷰어'로 공유, ID를 DRIVE_FOLDER_ID로 등록
├─ 통합 실적 관리자료_YYYYMMDD.xlsx       ← 가장 최근 수정본 사용 (구글 스프레드시트도 가능, 시트 이름·양식 유지)
└─ 3. 연구실 앨범/                        ← 이름에 '앨범'이 들어간 폴더
   ├─ 국제 학술활동/
   │  └─ 260913 IEEE ITSC 2026 (나폴리)/  ← 'yymmdd 행사명' (261022-23 같은 기간 표기도 가능)
   ├─ 국내 학술활동/
   ├─ 연구 및 대외활동/
   └─ 연구실 생활/
```

- 실적: 엑셀을 고쳐 다시 올리면 논문·과제·특허·수상·학술대회·저서가 갱신됨. 홈페이지에서 따로 보강한 논문 링크는 제목이 같으면 유지됨.
- 숨길 실적, 엑셀에 없는 실적 추가는 `public/overrides.json`의 `exclude`, `add`에서 관리.
- 사진: 앨범 폴더를 추가·수정·삭제하면 사진 앨범에 반영됨. 사진 없는 빈 폴더는 표시되지 않음. 사진은 파일 이름순, 첫 사진이 대표 사진. jpg·png·webp만 반영(동영상·pdf 제외).
- 폴더 이름 앞 날짜가 앨범 날짜·연도가 됨. 날짜가 없으면 폴더 수정일로 대체됨.
- 분류 폴더 이름이 그대로 사진 앨범 탭 이름이 됨.
- 전 홈페이지(tris)에서 옮겨온 앨범 63개는 그대로 표시됨. 같은 사진을 드라이브에도 올린 경우 `public/overrides.json`의 `hideLegacyAlbums`를 `true`로 바꾸면 드라이브 앨범만 표시됨.

### 최초 1회 설정
1. Google Cloud Console(console.cloud.google.com)에서 프로젝트 생성 (hy.tsilab 계정 권장)
2. 'API 및 서비스 → 라이브러리'에서 **Google Drive API** 사용 설정
3. 'IAM 및 관리자 → 서비스 계정'에서 서비스 계정 생성 → '키' 탭 → 키 추가 → JSON 다운로드
4. 연동 폴더를 서비스 계정 이메일(…@….iam.gserviceaccount.com)에 **뷰어**로 공유
5. GitHub 저장소 → Settings → Secrets and variables → Actions → New repository secret
   - `GDRIVE_SA_KEY` : 다운로드한 JSON 파일 내용 전체 (채팅·메일 등에 붙여넣지 말 것)
   - `DRIVE_FOLDER_ID` : 연동 폴더 주소 `drive.google.com/drive/folders/여기부분`
6. Actions 탭 → Deploy to GitHub Pages → Run workflow로 첫 동기화 확인

설정 전에는 동기화 단계만 건너뛰고 배포는 정상 진행됨.

### 다른 자료 추가 연동
논문 PDF, 공지, 구성원 사진 등 다른 폴더도 같은 방식(`scripts/sync-drive.mjs`에 폴더 규칙 추가)으로 연동 가능함.

## 3. 코드 구조
- `app/` : 화면(Next.js, 정적 내보내기)
- `public/*.json` : 홈페이지 데이터 (실적·앨범·구성원·연구·과제 등)
- `scripts/sync-drive.mjs` : 드라이브 → 데이터 동기화
- `scripts/convert-achievements.mjs` : 실적 엑셀 → `achievements.json`
- `.github/workflows/deploy.yml` : 동기화 → 빌드 → 배포
